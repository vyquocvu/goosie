Evidence (2026-11-18, landed on `plan/R1-font-shorthand-wide-keywords` as `3aa25467` on top of the R-0 commit `ca4de306`; base `ea26ab01`, nothing pushed or merged).

Mechanism, from source before fixing: `internal/css/value.go:50` maps a bare keyword to `ValueInherit`/`ValueInitial`/`ValueUnset` and only a longhand's value reads those, while a shorthand is expanded by parsing components — grepping the three constants in `internal/style` returned zero matches, so nothing consumed them. `font: inherit` on a control therefore kept the UA 13.3333px Arial that BR-276 installed, which is why this only became visible after the UA sheet carried a control font.

Measured before coding (`scripts/verify-fontwide-keywords.js`, exit 0, Playwright 1.63.0 / chromium-1243 / 153.0.8010.12): `inherit` → 16px sans-serif; `initial` → 16px Times 400 normal, line-height normal; `unset` → identical to `inherit` because every font longhand inherits; `font: inherit bold 12px Arial` invalid as a whole declaration; `font: 12px Arial inherit` legal (the second word is a custom-ident family token, so this is a two-word family, not a keyword); a longhand declared after the keyword still wins inside the group. Two of these corrected assumptions inherited from the defect text, and the 174×24 target it names is gated: `internal/layout/block.go` pins a 145px content width for text fields under `GOOSIE-CONTROLWIDTH-001`, so this slice claims heights (24/22/24/42) and face only.
